# 本地桌面界面技术提案（桌面方向已批准，正式实现待 Demo 确认）

**用户已批准直接采用 Tauri 2 桌面 APP 方向。** 推荐 React + TypeScript + Vite，业务通过窄 Rust commands 调用共享核心；受控媒体通路读取已提交公开混音。此前 Axum 通用浏览器入口后置，不现在双套开发。本轮只有离线 HTML、CSS、演示脚本和文档，没有搭正式工程、安装依赖、监听端口、操作真实会议或启动模型。**新版明暗 Demo 经用户确认后才进入正式开发。**

已确认：会议详情顶部回听、行动项只读（不做跟进系统）、今日/本周/最近3天/最近7天且默认7天；桌面方向获准，不等于以下新增管理策略都已冻结。

## 一、主推组合

| 层面 | 选择与边界 |
| --- | --- |
| 前端 | React + TypeScript + Vite，离线打包资源；复用当前版式和组件交互，不将静态脚本当正式工程。 |
| 样式与控件 | [Radix Colors](README.md#明暗外观与开源配色) 的 Slate/Teal 与状态色，本地 CSS tokens；正式阶段按需采用 Radix UI 的无样式 Dialog/Tabs，原生表单优先，不安装整套管理后台。Colors 调色板不等于引入 UI 可执行库。 |
| 数据与草稿 | TanStack Query 管理异步查询缓存、失效和有界轮询，不要求 HTTP；组件草稿留本地状态，不让缓存成为业务真相。 |
| 桌面入口 | Tauri 2，在 macOS 使用系统 **WKWebView**，不内置 Chromium。前端通过类型化适配器调用窄 commands；原生权限、安全和打包仍需验证。 |
| 核心复用 | CLI 与桌面共用 Rust 应用用例、Store/AppConfig/安全产物读取；通过既有身份 socket 控制唯一 service，不包装 CLI stdout。 |
| 媒体 | 优先已提交 Ogg/Opus 公开混音，以分段偏移映射整场；评估受限资产/自定义窄协议的 Range、句柄与读者锁，不传整场 base64。见[官方音频研究](audio-research.md)。 |
| 分发 | Tauri 内嵌本地构建资源；保留原 helper/worker/原生库/模型与依赖许可。前端不需 Node 服务，Pi 原有 Node 依赖不变。 |

React/Vite、样式、控件和查询缓存均可沿用先前前端建议，但页面不散落 `invoke/fetch`。业务接口在桌面适配器调用 commands；媒体 URL、导出与窗口操作各有明确边界。未来确需浏览器入口，再实现 HTTP 适配器及 Axum 网关，沿用共享用例；当前不建设端口/会话系统。依赖版本在正式开发获准后核对稳定兼容版、锁文件及许可，本轮未安装。

## 二、进程、生命周期与唯一业务来源

```text
React 界面 → 类型化桌面适配器 → Tauri commands → 共享 Rust 用例/SQLite
                                                   └→ 身份 socket → 唯一 service
播放器 → 受控窄媒体协议 → 已提交公开 mix                            ├ Swift helper
                                                                 └ 持久处理管线
```

- 复用当前 runtime/XDG/profile 解析、根冲突、socket UID/PID/实例身份检查，不另造 locator；不自动安装、拉起或复制服务。服务未运行时可在已有根安全读取历史，录音入口说明不可用和启动方式。
- 从 `src/cli/mod.rs` 提炼列表、结果选择、入队、重试和配置修改等可测用例，CLI 与 commands 只做输入输出转换。Store 事务/产物校验唯一负责业务不变量；桌面不执行管线或 claim 任务，不建立第二个录音 owner。
- 建议关闭窗口或退出 APP 不停止独立服务/录音/任务；**停服务是另一项显式操作**，仍须等待录音封存。具体窗口行为待实现设计明确，不本轮增加托盘。托盘/原生通知是 Tauri 可用能力，不是已批准功能或已获系统权限，既有 OMM 通知不升级成独立身份承诺。
- commands 做有界小型请求，阻塞数据库/校验放受限执行器；定义大小、分页、超时、并发与返回正文上限。稳定错误码区分 partial/committed/unknown；Rust 与 TypeScript 用共享样例核对类型，不冻结正式协议。
- 数据仍在原 STATE SQLite，产物仍在 DATA，CONFIG/Pi 专用目录和 CACHE 分类不变；目录0700、敏感文件0600。只读不暗中迁移；新增写入能力需获批迁移与事务。
- 当新 attempt 失败仍应读已提交、hash 通过的旧结果；不能照搬 `meeting read` 的最新 attempt 就等同最新成功结果。历史只读按明确 attempt 取既有文件，不复制会议到网页存储。
- 本机自然日筛选由接口解释为明确时区区间，不照搬 CLI 的 UTC 日期比较。全文检索限定已提交文本、限额分页，不扫描整盘或先建另一套真源。
- 元数据标题/备注/标签须纳入原存储及并发规则，不能覆盖原始证据文件。配置复用 `AppConfig::set/validate/save` 白名单和私有原子写入；批量修改需条件保存，CLI 同样协调，冲突不静默覆盖。生效依 helper/编码/任务快照分开说明，不将落盘等同全部立即生效。

## 三、音频边界与待验证项

`src/core/store/archives.rs` 的 `meeting_audio` 提供已完成归档 mix 的 sequence/采集帧位置。当前公开归档是48kHz单声道 **Ogg 容器 + Opus 编码**，可能分段；原 WAV 可能合法清理，旧会议未必有新归档清单。

[WebKit 官方](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/#media)已明确 macOS Sequoia **15.4** 的 WebKit for Safari 18.4 加入 Ogg/Opus，不再以「Safari 也许不支持」为笼统结论。但 Tauri 用系统 WKWebView，独立 Safari 的版本不足以判断；本轮未核对或实测目标运行环境。PCM WAV 有 Apple 原生格式依据，具体参数/协议/seek 仍需合成无声验证，详见[研究记录](audio-research.md)。

建议按以下门槛做正式设计，而非先承诺 WAV 缓存：

1. 用自产合成无声文件在目标 WKWebView 验证实际解码、时长、倍速、段内/跨段跳转。播放器以段偏移映射整场，不能生硬拼接 Ogg 或假设跨段共用 byte Range；未归档/有缺口明确显示。
2. 资产协议虽已有 Range 基础，`convertFileSrc` 不自动提供 OMM 安全语义。窄媒体请求只接不透明标识，查提交收据后校验受控根、所有权、symlink、类型/大小/hash，持有已验证句柄并继续保持读者保护，防清理/替换竞态。不能公开 DATA 或只做路径字符串白名单。
3. 验证206/Content-Range/Accept-Ranges、416、条件读取/产物标识、取消释放及并发预算；限制多范围与内存，真实 MIME、不缓存敏感内容、不返回目录或路径。每个请求仍经过身份/业务授权，不经通用 invoke 返回整场音频 base64。
4. 若目标解码确有缺口，再确认按已校验公开 mix 用现有固定受控工具生成有界 PCM WAV 缓存，输入 hash/版本、容量/并发/清理均受控。不改变归档、转写引擎或模型，不回听内部 mic/system，不引入随机系统编码器。现有读者锁/hash/cleanup 保护不因换容器而减少。

当前未搭 Tauri、未解码或播放。技术无声验证与可听播放授权分开；真实录音/权限/听感验证须明确单独获准。

## 四、长任务与新增能力差距

建议先用**有界查询轮询**（通过 commands，不要求 HTTP）：活动队列约2秒小投影，静态页约10秒或操作后失效刷新；隐藏窗口降频、失败退避、回到前台刷新、限制并发。正文按需加载，SQLite 重建视图，界面计时器不拥有任务；调用超时不自动取消处理。未来有证据再加事件推送，不建另一条事件真源。

| 原型能力 | 既有差距与待确认策略 |
| --- | --- |
| 手动创建 | 已有 start/stop socket；保留录音范围知情确认、原系统权限，unknown 不伪装就绪。 |
| 编辑 | 无通用元数据用例；拟限标题/备注/标签，不改识别正文与采集事实；需 Store 迁移与冲突规则。 |
| 删除/批量删除 | 无现有接口；建议首版可恢复回收站，禁止在途会议删除、音频/文本/旧尝试共同保留，不自动物理清理；仍待确认。 |
| 导入 | 无现有入口；建议先单个封存混音 WAV/Ogg-Opus，限制大小/时长/声道，私有 staging 校验/hash 后入原队列。日期/时区、重复/失败清理须确认；不虚构双声源。 |
| 重新处理 | 复用 all/transcribe/summary、force/retry。建议转写后衔接纪要，重新纪要只用完整提交转写；成功前保留旧结果，不新增文本外发审批。真实阶段语义不能仅凭 Demo 改写。 |
| 取消 | 现无按任务取消入口；需持久取消意图及 worker 安全点，待执行/运行中分别处理。等待自有子进程退出再清 workspace/读者锁，保留音频与已提交资料；提交竞态事务裁决，未知孤儿不盲杀 PID。 |
| 历史阅读 | 现有 attempt/journal/hash，不等于完整版本产品。只读既有成功产物、标各自来源；未提交只显示状态，不合成不存在的历史或擅加回滚。 |

以上需与 CLI/service 共用事务，不在桌面壳中单独拼装。例如删除与任务领取互斥、CLI 与界面配置同规则、取消和 journal 提交确定裁决。

## 五、安全、打包与依赖

- 只载打包本地资源，CSP 严格限制脚本、连接、媒体协议和 frame/object，不开远程页面或泛化 shell/fs。正文不可信，文本转义；Markdown 限语法/净化，不运行原始 HTML。导出显式操作、净化文件名。
- Tauri capabilities 最小授权，但[官方明确](https://v2.tauri.app/security/capabilities/)：注册的应用自定义 commands **默认可被全部应用窗口/webview调用**，需用 `AppManifest::commands` 等显式纳入权限体系；不能以为写了 capability 就自动限制所有业务命令。每个 command 仍须验证参数、调用来源与业务权限，校验不透明ID/根/状态，不接受任意路径或命令。
- 不用 HTTP 减少端口、会话和跨站请求面，仍有内容注入/进程通信/媒体协议风险。未来如加 Axum，要单独设计回环绑定、Host/Origin、一次性引导、会话及防跨站请求，不能默认开放 loopback 端口。
- 日志只记录安全错误码/操作类别/耗时，不记会议正文、标题、搜索词、认证、原始 stderr 或绝对路径。配置表单只含非秘密白名单；可执行路径仍受信校验，不能由会议正文驱动。Pi 保持专用目录、禁个人工具/扩展/上下文，不增加文字上传审批。
- 开发需已有 Rust、Node 和 Xcode 工具；正式阶段才锁前端/Tauri稳定版本与测试依赖。不得自动安装系统工具、浏览器或第三方包。运行需原 OMM 依赖及系统 WKWebView；不承诺模型、权限、认证就绪，不引入 Python。
- Tauri `.app` 不自动继承 capture helper 身份或取得系统权限。需核对 bundle/嵌套 helper 签名、entitlements、socket peer身份和录音封存；不替换 Swift/Yulu 采集内核或冒用原身份。
- [macOS 签名文档](https://v2.tauri.app/distribute/sign/macos/)区分个人本机 ad-hoc 与公开分发 Developer ID/公证。个人开发不要求用户提供个人证书，不把 ad-hoc称为公证。升级保留 DATA/STATE/CONFIG、0700/0600及原依赖许可。
- Tauri 跨平台外壳不会移植现有 macOS 采集和 Lark 逻辑；本轮不承诺 Windows/Linux，也不扩托盘、原生通知、安装/卸载/下载或远程访问。
