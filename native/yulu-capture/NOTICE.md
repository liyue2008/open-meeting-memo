The source read during this port has SHA-256 `34fc075a2f04efbf2f384ffad76cf1845f91358cb4004e2575df551b6eaea785`. ## Deliberate differences

- Independent `OMMCapture.app` / `org.openmeetingmemo.capture` identity; development build targets arm64/macOS 13 with ad-hoc signing. No Yulu TCC identity, certificate, icon, Python runtime or service installation is copied. This is not notarized release packaging.
- Mandatory canonical private environment directories supplied by Rust: `YULU_APPLICATION_SUPPORT_DIR` = STATE/omm/capture; `YULU_LOG_DIR` = STATE/omm/logs; `YULU_MEDIA_LIBRARY_DIR` = DATA/omm/meetings; `YULU_IPC_DIR` = current RUNTIME/omm/capture. These names are compatibility projection only. No fallback to real Yulu configuration; only optional `config.json` in projected STATE is read. No runtime fallback is supplied by capture.
- No startup permission-probe scheduling. Explicit recording start and original interrupted-recording recovery still arm the original capture sources; status never launches the helper. The backend probe methods themselves remain copied.
- Idle-only EOF JSON `quit` now requires matching `instance_id` and `captureIPCVersion:1`, rejects recording or mismatched identity/version, and replies `{status:"bye",instance_id,captureIPCVersion:1,pid}`. Once accepted, subsequent controls are rejected. Production schedules `NSApp.terminate`; synthetic `--ipc-fixture` explicitly stops its listener and exits because it has no NSApplication loop. Listener cleanup compares the bound socket's device/inode and never removes a replacement endpoint. The audio backend, PCM, WAV and recovery algorithms are untouched.
- EOF JSON protocol retains `start/stop/status/windows/audio_devices`. Start requires UUID `session_id`, UUID `instance_id` matching `YULU_SERVICE_OWNER`, `output_dir`, basename `filename` ending `.wav`; it refuses duplicate start. Exact filename is an outer naming override, not a WAV algorithm change. Stop requires matching IDs. Status adds those IDs and `files`; stop returns all `files`, including previous resumed segments. AX window IDs are unavailable in the original helper, so Rust returns `WindowInfo.id=0` (unknown). Devices return input devices with `default_input_uid` from CoreAudio, not fabricated defaults.
- `omm-session.json` atomically retains session/files, including the last stopped session for stop retry/reconciliation. The original `.state.json`, WAV head patch cadence, PCM/downmix/synchronization, ScreenCaptureKit, AVAudioEngine, process tap/private aggregate, route rebuild and zero-buffer recovery algorithms remain copied. Recovery continues in the prior segment directory and appends a generated segment filename. The `Yulu DualTrack v1` WAV marker intentionally remains byte-identical (82-byte header).
- Silence callback is no longer a Python process: `OMM_SERVICE_SOCKET` receives EOF-framed JSON `{schema_version:1,command:"capture_auto_stop",session_id,instance_id}` and replies EOF-framed `{ok:true}` to acknowledge acceptance. No shell, executable discovery, or audio/text upload. At failure the original silence fallback stops locally; retained files remain discoverable by service reconciliation. Rust must reconcile status before stopping and acknowledge only after durable acceptance. Callback does not itself write DB or queue ASR.
- Copied capture diagnostics are reduced to generic `capture event` to avoid persisting paths, window titles, errors or device identifiers. umask 077 / original private WAV creation apply. Development test entry points use synthetic PCM/hooks, never real capture or permission probes.

## Frame-based rolling perimeter

`RollingRecordingWriter` is a narrow outer wrapper around the unchanged `WavWriter` and already paired stereo PCM on the existing serial queue. Its reference is the **uncommitted development snapshot**, not a released Yulu feature, at repository-relative `yulu/scripts/audio_daemon.swift:578–704` in Yulu's `segmented-recording` development worktree, branch `feat/segmented-recording`, HEAD `66f8468634b27933c23865da1e7c09b50bd3cf5a`, SHA-256 `050dd5f5c1967845c28ab6a996bd196fcd82c6e0b35e2365439cee800c2d2ddc`. The reference was read only and its hash rechecked; its MIT attribution is retained. OMM does not copy its host configuration, authentication, recordings or Python runtime.

A boundary splits an append on the exact paired-frame index (default/maximum `1800*48000`), finalizes the previous WAV, and publishes an immutable `*.sealed.json` descriptor for host admission. It does not restart acquisition, flush source buffers, or reset synchronization. SQLite owns the queue; the helper never encodes or calls ASR. Public CLI and helper both use integer `segment_ms` (60000–1800000); the legacy default 3600000 is clamped in memory, without rewriting user configuration. Stop finalizes only a nonempty tail; recovery continues through the existing acquisition/recovery kernel with an outer rolling writer. Descriptors remain until durable host admission; archived history need not be reread from removed temporary WAVs. Synthetic fixtures prove payload concatenation, a virtual 30-minute threshold, empty tails and interrupted-writer recovery; they do not prove real-device gaplessness or sleep/route quality.

The original audio acquisition, PCM pairing/downmix/synchronization, WAV header/marker and repair bodies remain unchanged and are source-hash guarded in `tests/capture_source_contract.rs`. Background Ogg/Opus encoding belongs to the Rust perimeter, not a replacement recorder.

The startup IPC gate opens only after the existing recovery, bridge/state publication and synthetic-fixture PCM acknowledgement complete. A valid zero-frame current WAV is retained on disk but excluded from the logical sealed manifest; sequence/frame origin remain derived from the actual nonempty descriptors. Truncated or malformed sources still fail conservatively. Recovery descriptors include a strictly typed `legacy_wav` flag; legacy or non-temporary sources are never cleanup candidates. The host's bounded `audio.opus_bitrate_kbps` (32/48/64/96, default 48) is frozen on admission and does not alter this capture helper or re-encode historical archives.

## Service integration and recovery

Construct `MacCaptureAdapter::new(CapturePaths, helper_instance_uuid, timeout)` using existing canonical 0700 directories. `launch_helper(bundle_executable, service_socket)` is an **explicit** action returning a child for core to monitor/reap. Persist the helper instance UUID; do not rotate it solely on service restart. No helper launch occurs in adapter construction or methods. Before restarting a helper, query its existing socket. After service restart, call `status()` and reconcile `recording/path/session_id/ready/errors` against durable meeting state: never repeat `start()` just because the service lost its in-memory state. A different helper instance fails with conflict, not empty/idle success.

`CaptureAdapter::stop()` hashes and validates WAV segments under DATA and returns sample-derived durations; it does not submit transcripts, summaries, DB rows or enqueue work. Even when status says idle, retained session files allow retrying stop after local silence fallback or lost responses. Core must suppress duplicate sealing/queueing and record restart/route/sleep gaps. A killed segment's header may describe only the last 5-second patch; this copied limitation is not claimed fixed. RIFF UInt32 limit and mic sample-rate assumptions remain original limitations. Core owns controlled segmentation and recovery decisions.

### Normal service stop, including an adopted helper

After successful sealing/recording reconciliation, call the concrete adapter's `pub async fn shutdown(&self) -> Result<()>`; this is **not** a new `CaptureAdapter` trait method. It does not stop or seal a recording itself. Core must invoke it even when no owned `Child` remains after service restart, propagate failure on stop/uninstall, and reap an owned child separately after confirmed exit. Keep the persistent capture-instance UUID and the existing constructor timeout.

The timeout bounds the entire operation, including the internal operation mutex, status, quit, and process-exit wait. Only a canonical private, current-UID 0600 socket is accepted. On macOS, kernel `LOCAL_PEERPID` binds the socket peer to a PID; status must match that PID, the persistent instance UUID, protocol version, and idle state. A per-process `kqueue` `EVFILT_PROC/NOTE_EXIT` observer is registered while connected **before** status/quit. Quit uses a fresh connection only after the socket device/inode and peer PID are rechecked. Its EOF-framed acknowledgement must repeat PID/instance/version and `status:"bye"`. Success requires the observed process-exit event **and** endpoint absence, not just an acknowledgement or disappearing socket. No PID-file trust, `kill(pid,0)` polling, signals, forced process kill, or adapter-side unlink is used.

Wrong identity/version/recording or a replacement endpoint returns `conflict`; malformed acknowledgement returns `corrupt`; missing/unreachable endpoint or unavailable kernel evidence returns `unavailable`; an exited process leaving its original socket returns `io`; unconfirmed exit/response returns `timeout`. These errors do not mark shutdown successful. Retry is idempotent only on the **same adapter** after verified successful exit, with the endpoint still absent. A new adapter with no endpoint cannot prove an earlier process exited and returns `unavailable`; any new endpoint after cached success returns `conflict` and is left untouched. Treat a successfully shut-down adapter as terminal; explicitly construct a new adapter for a later helper lifecycle. This preserves identity on service adoption without silently targeting a replacement helper.

The kernel observer is macOS-only; other systems return `unavailable` rather than claiming process verification. Synthetic fixtures test prestarted/adopted helper normal exit, rejection, timeout, acknowledgement validation, and replacement/stale endpoint handling. Real hardware recording, TCC, macOS 13 execution, and production NSApplication termination remain unverified. This perimeter fix is not an audio-kernel rewrite or a global process-cleanup policy.

This builds/signs/verifies only; never launches capture. macOS 13 runtime/TCC, both source audibility, Bluetooth/sleep and actual recovery are unverified. Permission capability reduction is not an OS sandbox.
